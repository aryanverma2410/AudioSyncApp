# SyncWatch Mobile – Handover Guide

This document describes how to turn the **SyncWatch** web application (located in `syncwatch/web`) into native Android, iPhone, and iPad applications using **Capacitor**. It also covers connecting the app to the Cloudflare Workers signaling server used for WebRTC peer‑to‑peer communication.

---

## 1. Repository Overview (mobile‑relevant files)
| Path | Purpose |
|------|---------|
| `src/` | React source code (shared between web and mobile). |
| `public/` | Public assets (favicon, icons). |
| `index.html` | Entry point – already includes a responsive `<meta viewport>` tag. |
| `capacitor.config.ts` | Capacitor configuration – defines the native app ID, name, and web assets directory (`dist`). |
| `package.json` | Updated with Capacitor dependencies (`@capacitor/core`, `@capacitor/cli`) and scripts for building native projects. |
| `README.md` | General project description (see the top‑level `syncwatch/README.md` for an overview). |
| `handover-mobile.md` | **This file** – step‑by‑step run‑book for mobile developers. |

## 2. Prerequisites (local machine)
| Platform | Required Tools |
|----------|----------------|
| **Common** | Node ≥ 18, npm, Git, **Capacitor CLI** (installed via npm). |
| **Android** | Java ≥ 11, Android Studio (or Android SDK + command‑line tools). Ensure `ANDROID_HOME` is set and `adb` is in your `PATH`. |
| **iOS (iPhone/iPad)** | macOS, Xcode ≥ 15, Apple Developer account (for signing). |

> **Tip:** The Capacitor docs provide detailed installation steps: https://capacitorjs.com/docs/getting-started

## 3. Install Capacitor & Dependencies
```bash
cd syncwatch/web
# Install Capacitor core and CLI (already listed in package.json)
npm install
# Install any additional native plugins you may need later (e.g., @capacitor/network)
# Example: npm i @capacitor/network
```

---

## 4. Add Mobile Platforms
```bash
# Add Android project
npx cap add android

# Add iOS project (macOS only)
npx cap add ios
```
These commands create `android/` and `ios/` directories inside `syncwatch/web`.

---

## 5. Configure Native Projects
### 5.1 Android (`android/app/src/main/AndroidManifest.xml`)
Add the following permissions inside the `<manifest>` tag if they are not already present:
```xml
<uses-permission android:name="android.permission.INTERNET" />
<uses-permission android:name="android.permission.CAMERA" />
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```
Also, ensure the `minSdkVersion` is at least **21** (Capacitor default). No additional changes are required for WebRTC – the native WebView supports it out of the box.

### 5.2 iOS (`ios/App/App/Info.plist`)
Add the following keys to request camera and microphone access:
```xml
<key>NSCameraUsageDescription</key>
<string>SyncWatch needs camera access for screen‑share and webcam features.</string>
<key>NSMicrophoneUsageDescription</key>
<string>SyncWatch needs microphone access for voice chat.</string>
<!-- Allow clear‑text to wss (WebSocket over TLS) – usually not needed, but keep for dev -->
<key>NSAppTransportSecurity</key>
<dict>
    <key>NSAllowsArbitraryLoads</key>
    <true/>
</dict>
```
The default Xcode project generated by Capacitor already includes the required `NSAllowsArbitraryLoadsInWebContent` for WebViews, but adding the above ensures no runtime permission prompts are missed.

## 6. Build the Web Assets
Capacitor serves the compiled web files from the `dist` folder defined in `capacitor.config.ts`.
```bash
npm run build   # Produces ./dist/ with the bundled React app
```
After a successful build, copy the assets into the native projects:
```bash
npx cap sync   # Copies ./dist to android/app/src/main/assets/public and ios/App/public
```
You can also run `npx cap copy` if you only want to copy assets without updating plugins.

---

## 7. Run / Test on Devices
### Android (Emulator or Physical Device)
```bash
# Open Android Studio and run the project, or use the CLI:
npx cap open android   # Opens the Android project in Android Studio
# In Android Studio: press ▶ (Run) to launch on the selected emulator/device.
```
You can also launch directly via Gradle:
```bash
cd android && ./gradlew assembleDebug && ./gradlew installDebug
```
### iOS (Simulator or Physical Device)
```bash
npx cap open ios   # Opens the Xcode workspace
# In Xcode: select a target (iPhone 15, iPad Pro, etc.) and click Run (⌘R).
```
**Signing:** Choose your Apple Development team in the Xcode project settings and ensure a valid provisioning profile.

## 8. Connecting to the Cloudflare Workers Signaling Server
The web app (and the extension) communicate with the signaling server over a WebSocket URL defined in `src/hooks/useWebRTC.ts` (or similar). By default the placeholder is:
```js
const SIGNALING_URL = "wss://<YOUR_WORKER_SUBDOMAIN>.workers.dev";
```
### Steps to Deploy the Worker (once)
1. Install Wrangler (if not already): `npm i -g @cloudflare/wrangler`.
2. Login: `wrangler login`.
3. Create a worker project (outside the repo) and copy `syncwatch/signaling/src/index.ts` into it, or use the existing `syncwatch/signaling` folder:
   ```bash
   cd syncwatch/signaling
   wrangler init syncwatch-signaling --type=javascript
   cp -r src/* syncwatch-signaling/src/
   ```
4. Deploy: `cd syncwatch-signaling && wrangler deploy`.
5. Note the resulting URL, e.g., `https://my-syncwatch.workers.dev`.
6. Replace the placeholder in the React source (search for `SIGNALING_URL`):
   ```bash
   grep -R "SIGNALING_URL" -n src
   # Edit the file (e.g., src/hooks/useWebRTC.ts) and replace the placeholder.
   ```
7. Re‑run `npm run build && npx cap sync` to embed the new URL.

### Android

```bash

```
